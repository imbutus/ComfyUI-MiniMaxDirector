# Architecture

## One rule shapes everything

Anything that can be decided without the model is decided without the model.

That is why `lattice.py`, `timeline.py`, `compile.py` and `lint.py` import nothing but
the standard library. They hold the entire product — the frame lattice, the document, the
prompt, the checks — and they are exercised by a test suite that runs in under a second on
any machine. ComfyUI, torch and 50 GB of weights only enter at the edge, in `nodes/`.

## Layers

```
    web/                    timeline editor (canvas, plain ES modules)
      │  JSON document
      ▼
    nodes/director.py       ComfyUI-facing classes
      │
      ├── compile.py ───────► prompt string
      ├── lint.py ──────────► warnings and errors
      └── core.py ──────────► MiniMaxH3ImageToVideo / …ReferenceToVideo (ComfyUI core)
```

The arrows only point one way. Nothing under `src/minimax_director/` outside `core.py` and
`nodes/` knows ComfyUI exists.

## The document

All director state is one JSON object in one widget:

```json
{
  "version": 1,
  "fps": 24,
  "dialect": "timeline",
  "global_prompt": "Neon-lit alley after rain.",
  "shots": [{ "start": 0, "length": 24, "prompt": "Wide shot.", "camera": "dolly_in" }],
  "cues": [{ "start": 0, "length": 48, "prompt": "Distant siren." }],
  "references": [{ "kind": "picture", "index": 1, "label": "" }]
}
```

Consequences worth stating, because they were the point:

- A timeline can be copied between graphs, diffed in review, or generated by a script.
- A graph saved with the editor installed still loads and still runs without it — the
  widget is a view over the JSON, never a second source of truth.
- Frames are authoritative; seconds are derived at compile time only, so a timeline cannot
  drift by a rounding error.

## Reference slots

`references` in the document is *not* what the compiler trusts. The node rebuilds it from
the inputs that are actually connected before compiling, so `<Picture 2>` in the prose and
slot 2 in the graph cannot disagree. The linter then reports both directions: a token with
nothing wired is an error, a wired input nobody mentions is a warning.

## Talking to the core H3 nodes

`core.py` resolves `MiniMaxH3ImageToVideo` and `MiniMaxH3ReferenceToVideo` out of
ComfyUI's `NODE_CLASS_MAPPINGS`, reads the entry point off `FUNCTION`, and filters
arguments against the node's own `INPUT_TYPES()`. Optional inputs that a given ComfyUI
version does not declare are dropped rather than passed.

This costs one dictionary lookup and buys two things: we never restate upstream's
conditioning logic, and an upstream rename produces `CoreNodeMissing: … needs ComfyUI
0.30.0 or newer` instead of a `TypeError` from inside somebody else's call stack.

## Stubs, and why they are not in the package

The obvious design — ship mock nodes registered under the real core node names, so the
production workflow runs unmodified — **does not work**, and it is worth writing down why
so nobody tries it again.

`nodes.init_external_custom_nodes` snapshots `base_node_names = set(NODE_CLASS_MAPPINGS)`
*before* loading custom nodes and passes it to `load_custom_node` as `ignore`. The
registration line is `if name not in ignore: NODE_CLASS_MAPPINGS[name] = node_cls`, so a
custom node pack cannot replace a built-in. Worse, the failure is quiet:
`NODE_DISPLAY_NAME_MAPPINGS.update()` has no such guard, so the UI happily shows
"UNETLoader (mock)" while running the real class.

So the stubs live in `tests/graph/stubs.py`, and `tests/graph/harness.py` imports
ComfyUI in-process, calls `init_extra_nodes()`, and then patches the registry itself —
legitimate, because the test process owns it. It drives `execution.validate_prompt` and
`execution.PromptExecutor` directly, so the graph is checked by ComfyUI's own validator.

`CreateVideo` and `SaveVideo` are deliberately *not* stubbed. A passing run leaves a real
h264+aac mp4 on disk whose duration is `length / 24` — the frame lattice, observable from
outside the whole system.

## The editor

Canvas drawing inside the node ComfyUI already renders — no DOM overlay, no bundler, no
dependencies. `view.js` computes a geometry object and draws it; `interactions.js`
hit-tests that same object. Because both read one structure, what you see and what you can
click cannot drift apart.

`model.js` restates the frame lattice in JavaScript. Duplication is deliberate and both
copies are tested: the editor must not be able to express a length the compiler would
reject.

## Long pieces: windows that join

H3's trained range is roughly 5-15 seconds, so anything longer is generated in windows.
Splitting the timeline into separate workflows would work, but then the global prompt,
the shot list and the reference numbering exist in several places and drift apart.

Instead the document stays whole and carries a window (`start` plus `duration`).
`Timeline.advanced()` moves that window to the next piece, and `MiniMaxDirectorChain`
does the same at graph level while also handing back the previous window's final frame:

```
Director(window 1) -> sample -> VAEDecode --+--> CreateVideo
                                            |
                                            +--> Chain --> last_frame --+
                                                       --> timeline ----+--> Director(window 2)
```

Wire `last_frame` into the next Director's `first_frame` and the windows continue rather
than cutting. `overlap` re-renders a frame or two of the previous window, because a
window's first frame is a reconstruction of its guide rather than the guide itself, and
an editor needs something to cut on.

`more` reports whether content remains, so a loop stops instead of generating empty tails.

One upstream constraint makes this sharp-edged: `MiniMaxH3ReferenceToVideo` has no
`first_frame`. Reference conditioning and keyframe continuation are mutually exclusive in
the model, so the Director reports an error rather than silently dropping the guide.

## Known gaps

- Latent-space keyframe guides at shot boundaries are not implemented. They are only worth
  building if a real run shows the prompt-level timeline is not precise enough.
- Window chaining is built but has never run against real weights, so how visible a seam
  remains -- and how much `overlap` it needs -- is unmeasured.
- Reference slot counts (3 pictures, 1 audio, 1 video) mirror what the official template
  wires. Whether the model accepts more is untested.
- Which dialect H3 follows more faithfully — `[0s-1s]` timestamps or `SHOT 1:` ordinals —
  is unmeasured. Both ship; the document chooses.
